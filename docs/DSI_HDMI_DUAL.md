# Simultaneous DSI + HDMI on the CM5 uConsole

Physically validated on July 21, 2026, with Debian 13 ARM64, Hyprland 0.55.2,
Aquamarine 0.11.0, and Mesa/V3D.

## Final Result

The normal `bin/Hyprland` launcher starts:

- both KMS cards when the patched library is available, even if HDMI is
  disconnected at startup;
- DSI + HDMI when the connector is present, without restarting Hyprland;
- HDMI only as a recovery path if HDMI is connected but the prerequisites for
  dual mode are missing.

DSI always retains scale `1.0` and `transform 3`. The rules generated by the
wrapper initially place HDMI at `1280x0` as a safe recovery layout. After
startup, Kanshi applies `~/.config/kanshi/config`; the validated profile places
HDMI at `0x0` and DSI at `1440x0`, with HDMI on the left.

Neither `/usr/bin/Hyprland` nor Debian's Aquamarine library is replaced. The
patched variant is installed in isolation under
`~/.local/opt/aquamarine-0.11-uconsole/` and is loaded only for this uConsole's
multi-GPU profile.

## Topology That Caused the Failure

On this CM5, the relevant functions do not belong to the same DRM card:

```text
/dev/dri/card0       DSI KMS, normally DSI-2
/dev/dri/card1       V3D DRM device without KMS connectors
/dev/dri/card2       HDMI KMS, normally HDMI-A-1
/dev/dri/renderD128  only V3D render node
```

The scripts do not hard-code the `cardN` numbers. They resolve them from the
connectors under `/sys/class/drm` at every boot.

## Confirmed Causes

The problem had six layers:

1. Aquamarine 0.11.0 tried to associate each KMS card with a render node through
   its sysfs parent. The CM5's split topology prevented both DSI and HDMI from
   being associated with the sole `renderD128` node.
2. Assigning the node only when attaching the renderer was insufficient: EGL
   device selection still compared against the KMS file descriptor. The patch
   makes `AQ_RENDER_NODE` apply both when attaching the renderer and when
   locating the EGL device.
3. `LD_LIBRARY_PATH` did not guarantee that `start-hyprland` would load the
   isolated library. The wrapper runs Hyprland through
   `/lib/ld-linux-aarch64.so.1` with an explicit `--library-path`.
4. During early tests, the traditional profile rewrote
   `~/.cache/hypr/uconsole-monitors.conf` and added `DSI-2,disable`. The test now
   uses its own configuration under `$XDG_RUNTIME_DIR`, and the normal launcher
   directly generates the `dual` profile.
5. When HDMI was disconnected, Aquamarine destroyed its secondary renderer and
   called `eglTerminate` on the same `EGLDisplay` used by DSI. Mesa/V3D does not
   advertise `EGL_KHR_display_reference`, so DSI entered an
   `EGL_BAD_DISPLAY`/`EGL_NOT_INITIALIZED` loop and Hyprland terminated. The
   patch maintains a reference count only when that extension is unavailable
   and calls `eglTerminate` only after the final user disappears.
6. `swww` creates a reconnected output with a black background. The autoswitch
   now runs `uconsole-wallpaper output HDMI-A-1`, which loads the poster first
   and then the optimized GIF only on HDMI.

The hardware cursor also caused continuous retries for invalid 64x64 GBM
buffers. `cursor:no_hardware_cursors = true` is used only in the dual profile.

## Files That Implement the Solution

```text
patches/aquamarine-0.11-uconsole-render-node.patch
scripts/build-aquamarine-uconsole.sh
bin/Hyprland
bin/Hyprland-mgpu
bin/uconsole-hyprland-mgpu
bin/uconsole-display-switch
bin/uconsole-display-autoswitch
bin/uconsole-display-debug
```

The patch applies to Aquamarine `v0.11.0` at this exact commit:

```text
cd8321eba285e3cce50c50f19d5174a0b2567297
```

It includes the upstream fallback for systems with a single `renderD` node,
the topology-specific `AQ_RENDER_NODE` override, and manual lifetime management
for the shared `EGLDisplay` when the driver does not provide it.

## Rebuilding from Scratch

Install the build dependencies on Debian 13:

```sh
sudo apt install build-essential cmake ninja-build pkg-config git \
  libegl-dev libgl-dev libgles-dev libwayland-dev wayland-protocols \
  libseat-dev libinput-dev libhyprutils-dev libpixman-1-dev \
  libdrm-dev libgbm-dev libudev-dev libdisplay-info-dev \
  hyprwayland-scanner hwdata
```

From the repository:

```sh
cd ~/uconsole-hyprland-dotfiles
./scripts/build-aquamarine-uconsole.sh
./scripts/install.sh
```

The full installer performs both steps and also installs the dependencies:

```sh
./install.sh
```

Repeated builds are incremental. A new source tree starts at exactly Aquamarine
0.11.0; an existing patched tree must descend from that revision and contain
the complete patch.

The script installs nothing under `/usr`. If it finds a source tree with
unknown local changes, it stops instead of deleting them.

## Recoverable Test

Connect HDMI, close the graphical session, enter a TTY, and run:

```sh
uconsole-hyprland-mgpu check
uconsole-hyprland-mgpu test
```

`test` exits automatically after 90 seconds. It stores the log, DRM state,
`hyprctl monitors all`, and, when possible, separate DSI and HDMI screenshots
under `~/display-debug/`.

A successful result should show:

```text
DSI-2:     disabled: false, scale: 1.00, transform: 3
HDMI-A-1:  disabled: false, scale: 1.00, transform: 0
```

The Aquamarine log should contain:

```text
CDRMRenderer(drm): forcing EGL device match through /dev/dri/renderD128
Creating CDRMRenderer on gpu /dev/dri/renderD128
Modesetting DSI-2 with 720x1280@59.90Hz
Modesetting HDMI-A-1 with 1440x900@59.90Hz
```

The first GLES 3.2 creation attempt may return `EGL_BAD_MATCH`. On this machine,
that is expected if it then retries with GLES 3.0 and reports OpenGL ES 3.1 on
V3D.

## Normal Startup and Recovery

After a successful test, the normal startup command remains unchanged:

```sh
~/.local/bin/start-hyprland
```

The selected state is recorded in:

```sh
cat "${XDG_RUNTIME_DIR}/uconsole-hyprland-wrapper.log"
```

When the library and topology are available, it should report the following
with HDMI either connected or disconnected:

```text
MONITOR_MODE=dual
PATCHED_AQUAMARINE=1
```

If an update breaks the local variant, the launcher automatically falls back
to HDMI only. To recover the internal display, disconnect HDMI and restart
Hyprland. The experimental command never replaces the system library.

## Validated Hotplug

On July 21, 2026, a full cycle was completed with the new autoswitch:

1. Startup with DSI and HDMI active.
2. HDMI disconnect: DSI and Hyprland remained active.
3. Reconnect: HDMI returned at `1440x900` without restarting the session.
4. `swww` restored `fallout2.swww.gif` only on `HDMI-A-1`.

A correct Aquamarine log contains the disconnection and destruction of the
secondary renderer, but does not report `EGL_BAD_DISPLAY` or
`EGL_NOT_INITIALIZED` again. The autoswitch log should contain a sequence like:

```text
hotplug old=connected:HDMI-A-1 new=disconnected
hotplug old=disconnected new=connected:HDMI-A-1
wallpaper-restored output=HDMI-A-1
```

`uconsole-display-autoswitch` must not close Hyprland in this profile. A session
restart is reserved for the fallback used when the patched library is missing.
Kanshi configures mode, scale, rotation, and position. After each topology
change, the autoswitch reloads Waybar with `SIGUSR2` so its layer surfaces track
the new geometry. A full restart remains available through `Super+Shift+B`.
When HDMI reconnects, the poster loads first; the heavy GIF starts ten seconds
later in the background to avoid blocking DSI repainting.

### Revalidation with Kanshi and Waybar

On July 23, 2026, the physical cycle was repeated after Kanshi was added. DSI
remained visible and Waybar reappeared without using `Super+Shift+B`. The log
confirmed:

```text
hotplug old=connected:HDMI-A-1 new=disconnected
waybar-reloaded
hotplug old=disconnected new=connected:HDMI-A-1
wallpaper-restored output=HDMI-A-1
waybar-reloaded
```

If HDMI is disconnected again before the ten-second delay ends, the deferred
GIF loader detects that the output has disappeared and exits without treating
it as a failure.

## Validation Evidence

The user physically confirmed simultaneous output on both displays and the
complete hotplug cycle. Temporary screenshots were removed after the result,
cause, and reproduction steps were transferred to this document. The normal
launcher reported `MONITOR_MODE=dual`, both modesets, no 64x64 hardware-cursor
GBM retries, and no EGL loop after HDMI was disconnected.
